01 Навіщо квантовому інженеру ймовірності

Вимірювання кубіта — це підкидання монетки, нахил якої задав ваш алгоритм. Усе, що ви бачите, — статистика.

У класичному бекенді функція повертає значення. У квантовому — розподіл, і ви бачите не сам розподіл, а скінченну вибірку з нього. Один прогін схеми з вимірюванням в кінці дає один бітрядок, наприклад "0110". Цей прогін називають shot. Щоб щось дізнатися, схему запускають тисячі разів і отримують словник counts: {"0110": 512, "1001": 488}. З нього ви оцінюєте ймовірності, середні значення спостережуваних, вартість маршруту в QAOA і так далі.

Де саме ви використовуватимете цей матеріал щодня:

  • Вибір shots — це гроші. На IBM Quantum ви платите (або витрачаєте безкоштовні хвилини Open Plan) за час QPU. Подвоєння точності коштує вчетверо більше shots.
  • Порівняння "очікуване vs отримане" — тест чи debug: схема працює правильно, чи це шум?
  • Варіаційні алгоритми (QAOA, VQE, туторіал 4): класичний оптимізатор бачить зашумлену оцінку енергії, і від її похибки залежить, чи він взагалі зійдеться.
  • Mitigation: корекція помилок зчитування — це просто лінійна алгебра над розподілами ймовірностей (розділ 12).
Аналогія для фронтендера
Shot — це один відвідувач в A/B-тесті: він або конвертувався (1), або ні (0). Counts — ваша таблиця "скільки конверсій із скількох візитів", а оцінка ⟨Z⟩ з counts — той самий conversion rate з аналітики. Математика однакова до символу: похибка падає як 1/√N (√ — «корінь з»), тож щоб удвічі звузити похибку, треба вчетверо більше відвідувачів. Різниця лише у валюті: в A/B-тесті ви платите трафіком і днями, тут — секундами QPU.

02 Дискретні розподіли: Бернуллі, біноміальний, мультиноміальний

Три розподіли покривають майже все, що повертає квантовий комп'ютер.

Випадкова величина X — функція, що кожному результату експерименту ставить число. Для дискретної X закон розподілу задає функція ймовірностей (PMF) P(X = x), де всі значення невід'ємні і в сумі дають 1. Це і є словник {результат: ймовірність}, з яким ви працюватимете в Python.

Бернуллі: один shot одного кубіта

Вимірюємо один кубіт: результат 1 з імовірністю p, 0 з імовірністю 1 − p. Позначимо X ∈ {0, 1} (∈ — «належить»):

X ~ Bernoulli(p): E[X] = p, Var[X] = p(1 − p)

Дисперсія максимальна при p = 0.5 і дорівнює 0.25. Запам'ятайте цей факт: він дає "гірший випадок" для всіх розрахунків кількості shots.

Біноміальний: N shots одного кубіта

Повторюємо незалежно N разів і рахуємо кількість одиниць K:

P(K = k) = C(N, k) · pᵏ · (1 − p)ᴺ⁻ᵏ, E[K] = Np, Var[K] = Np(1 − p)

Частота p̂ = K/N (p̂ — «p з дашком»: оцінка, порахована з вибірки shots) — наша оцінка p. Її середнє дорівнює p (оцінка незміщена), а дисперсія в N² разів менша за дисперсію K:

E[p̂] = p, Var[p̂] = p(1 − p) / N, σ(p̂) = √(p(1 − p)/N)

Мультиноміальний: N shots n кубітів

Для n кубітів результатів 2ⁿ: бітрядки від "0…0" до "1…1". Кожен shot — один із них з ймовірністю pₓ. Вектор кількостей (K₀, K₁, …) має мультиноміальний розподіл. Кожна окрема координата Kₓ — біноміальна з параметром pₓ, тому всі формули для одного результату працюють і тут. Нове лише те, що кількості від'ємно корельовані: сума завжди N, і якщо "00" випало частіше, інші результати мусили випасти рідше (Cov(Kₓ, Kᵧ) = −N·pₓ·pᵧ).

💡
Головне з розділу: counts з квантового комп'ютера — це реалізація мультиноміального розподілу. Частота кожного бітрядка — оцінка його ймовірності з похибкою √(p(1−p)/N). Більше нічого магічного.

03 Правило Борна: від амплітуд до ймовірностей

Єдиний міст між квантовою механікою і статистикою.

Стан n кубітів — вектор з 2ⁿ комплексних амплітуд |ψ⟩ = Σₓ αₓ |x⟩ (|ψ⟩ — «кет псі»: вектор-стовпчик стану; Σ — «сума», велика сигма; α — «альфа»). Правило Борна: ймовірність отримати бітрядок x при вимірюванні в обчислювальному базисі

P(x) = |αₓ|² = αₓ · αₓ*, Σₓ |αₓ|² = 1

Умова нормування — це не "додаткова вимога", а наслідок того, що ймовірності мусять сумуватися в 1. Фаза амплітуди (наприклад, e^{iπ/4} (π — «пі»)) на ймовірність в цьому базисі не впливає: |e^{iφ}·a|² = |a|² (φ — «фі»). Але фаза впливає на те, що станеться після інших гейтів (інтерференція) — детальніше в туторіалі 8.

⚠️
Пастка №1 для новачка в Qiskit — порядок бітів. У ключі "01" правий символ — кубіт 0. Якщо ви рахуєте ⟨Z₀⟩, дивіться на останній символ рядка (bitstring[-1]), а не на перший. Половина "загадкових" багів у постобробці — саме тут.
born_rule.py
import numpy as np
from qiskit.quantum_info import Statevector

psi = Statevector([0.6, 0, 0, 0.8j])
print(psi.probabilities())          # [0.36 0.   0.   0.64]
print(psi.probabilities_dict())     # {'00': 0.36, '11': 0.64}

# те саме вручну: |a|^2 = a * conj(a)
amps = np.array([0.6, 0, 0, 0.8j])
print(np.abs(amps) ** 2)            # [0.36 0.   0.   0.64]

# вибірка з цього розподілу = те, що робить QPU (без шуму)
print(psi.sample_counts(shots=1000, qargs=None))  # напр. {'00': 361, '11': 639}

04 Очікуване значення і дисперсія

Математичне сподівання — це "постійна складова" випадкової величини, дисперсія — "потужність шуму" навколо неї.

Для дискретної величини:

E[X] = Σ x · P(x), Var[X] = E[(X − E[X])²] = E[X²] − E[X]², σ = √Var[X]

Три властивості, які знадобляться постійно:

  • Лінійність сподівання: E[aX + bY] = aE[X] + bE[Y] — завжди, навіть для залежних X, Y. Саме тому енергію ⟨H⟩ = Σ cᵢ⟨Pᵢ⟩ можна рахувати доданок за доданком.
  • Масштаб дисперсії: Var[aX] = a²·Var[X]. Множите спостережувану на 2 — похибка росте вдвічі, дисперсія вчетверо.
  • Сума незалежних: Var[X + Y] = Var[X] + Var[Y]. Для залежних додається 2·Cov(X, Y).

Застосуємо до середнього N незалежних однаково розподілених shots X̄ = (X₁ + … + X_N)/N (X̄ — «X з рискою»: вибіркове середнє):

E[X̄] = E[X], Var[X̄] = N·Var[X] / N² = Var[X] / N, σ(X̄) = σ / √N

Це одна з найважливіших формул туторіалу: стандартна похибка середнього (standard error, SE). Розкид одного shot — σ, а розкид середнього з N shots — σ/√N.

Аналогія для фронтендера
Lighthouse на тій самій сторінці дає різний Performance score від запуску до запуску (CPU, мережа, GC), тому Lighthouse CI робить кілька прогонів і бере медіану, а CrUX агрегує тисячі реальних візитів. Розкид одного запуску (σ) не зменшується — зменшується розкид середнього: 16 прогонів звужують його вчетверо. Shots — це ваші прогони. Де аналогія ламається: метрики швидкодії мають довгий хвіст, тому там люблять медіану й p75; кожен shot — чесний 0/1 з біноміальним розподілом, і звичайне середнє тут — правильна оцінка.

05 ⟨Z⟩, ⟨ZZ⟩ і парність бітрядка

Як з counts отримати те, що в квантових алгоритмах називають "очікуваним значенням спостережуваної".

Спостережувана Z (матриця Паулі) має власні значення +1 (стан |0⟩) і −1 (стан |1⟩). Вимірювання кубіта в обчислювальному базисі — це вимірювання Z: біт 0 означає "+1", біт 1 — "−1". Тому

⟨Z⟩ = (+1)·p₀ + (−1)·p₁ = p₀ − p₁ = 1 − 2p₁

Дисперсія одного shot: Z² = 1 завжди, тож Var[Z] = 1 − ⟨Z⟩². Максимум 1 при ⟨Z⟩ = 0. Звідси стандартна похибка оцінки ⟨Z⟩ з N shots:

SE(⟨Z⟩) = √((1 − ⟨Z⟩²) / N) ≤ 1/√N

Зверніть увагу: ⟨Z⟩ = 1 − 2p₁, тому похибка ⟨Z⟩ удвічі більша за похибку p₁. "±1% на ймовірність" і "±0.01 на ⟨Z⟩" — різні вимоги, і друга коштує вчетверо більше shots (задача 11).

Добутки Паулі: ⟨Z₀Z₁⟩ і парність

Для двох кубітів Z₀Z₁ має значення (+1)(+1), (+1)(−1) і т.д. Добуток знаків дорівнює (−1)^(b₀ + b₁) — це парність обраних бітів. Парна кількість одиниць дає +1, непарна −1. Узагальнення для будь-якої множини кубітів S:

⟨∏_{i∈S} Zᵢ⟩ = Σₓ p̂(x) · (−1)^(Σ_{i∈S} xᵢ)

Чудова властивість: з одного набору counts в Z-базисі ви отримуєте ⟨Zᵢ⟩, ⟨ZᵢZⱼ⟩, ⟨ZᵢZⱼZₖ⟩ для будь-яких кубітів одночасно. А от ⟨X⟩ чи ⟨XX⟩ вимагають іншої схеми: перед вимірюванням додають гейт H на відповідні кубіти (поворот базису). Саме тому EstimatorV2 групує доданки гамільтоніана за сумісними базисами — менше схем, менше shots.

💼
На співбесіді запитають так "Як з counts порахувати ⟨Z₀Z₂⟩ для 3 кубітів?" — Для кожного ключа беремо біти 0 і 2 (рахуючи справа), знак (−1)^(b₀+b₂), множимо на count, сумуємо, ділимо на N. Бонус: похибка не більша за 1/√N.
Частина II · Від shots до похибки

06 Закон великих чисел і магічне 1/√N

Частота прямує до ймовірності, але повільно. Наскільки повільно — каже σ/√N.

Закон великих чисел (ЗВЧ): для незалежних однаково розподілених shots середнє X̄_N прямує до E[X], коли N → ∞. Він гарантує, що оцінка колись стане точною, але не каже, наскільки точною вона буде за скінченного N. Відповідь дає стандартна похибка з розділу 4: розкид оцінки зменшується як 1/√N.

Подивіться на графік уважно. На перших десятках shots оцінка стрибає на ±20%, і це нормально, а не "кубіт зламався". Після тисячі shots вона в межах ±3%. Щоб дійти до ±1%, треба близько 10 000 — і жодним "розумним" трюком постобробки це не обійти, бо інформації у вибірці просто немає.

Правило "4×": щоб удвічі зменшити статистичну похибку, потрібно вчетверо більше shots. Щоб у 10 разів — у 100 разів більше. Це закон, не властивість конкретного заліза.

07 Центральна гранична теорема і довірчі інтервали

Чому скрізь з'являється 1.96 і як записати результат "чесно": p̂ ± похибка.

ЦГТ: сума (і середнє) великої кількості незалежних величин зі скінченною дисперсією приблизно нормальна, незалежно від того, як розподілений один доданок. Для частоти:

p̂ ≈ 𝒩(p, σ²), σ = √(p(1 − p)/N)

Біноміальний розподіл на графіку розділу 2 вже виглядає як дзвін саме через ЦГТ. Практичне правило застосовності: Np ≥ 10 і N(1−p) ≥ 10, тобто принаймні по десятку результатів кожного типу.

Інтервал Вальда (нормальний)

p ∈ [ p̂ − z·√(p̂(1−p̂)/N), p̂ + z·√(p̂(1−p̂)/N) ], z = 1.96 для 95%

Тлумачення "95%": якщо повторювати весь експеримент багато разів, приблизно 95% таких інтервалів накриють справжнє p. Це не "з імовірністю 95% p лежить тут" в баєсівському сенсі, але для інженерної практики відмінністю можна знехтувати.

Інтервал Вілсона: коли p̂ близько до 0 або 1

Вальд ламається на краях: при 0 одиниць зі 100 він дає інтервал [0, 0], ніби ми точно знаємо, що p = 0. Для квантових задач це типова ситуація: "заборонені" стани (наприклад, "01" у стані Белла) мають бути рідкісними. Інтервал Вілсона (Wilson score) поводиться коректно:

центр = (p̂ + z²/2N) / (1 + z²/N), півширина = z·√(p̂(1−p̂)/N + z²/4N²) / (1 + z²/N)

Для 0 зі 100 він дає [0, 0.037]. Швидка оцінка без формул — правило трьох: якщо подія не трапилась жодного разу за N спроб, верхня межа 95% приблизно 3/N.

intervals.py
import numpy as np
from scipy.stats import norm

def wald(k, n, conf=0.95):
    z = norm.ppf(0.5 + conf / 2)            # 1.95996 для 95%
    p = k / n
    h = z * np.sqrt(p * (1 - p) / n)
    return p - h, p + h

def wilson(k, n, conf=0.95):
    z = norm.ppf(0.5 + conf / 2)
    p = k / n
    d = 1 + z**2 / n
    c = (p + z**2 / (2 * n)) / d
    h = z * np.sqrt(p * (1 - p) / n + z**2 / (4 * n**2)) / d
    return c - h, c + h

print(wald(2880, 10_000))    # (0.27912, 0.29688)
print(wilson(2880, 10_000))  # (0.27921, 0.29696)  — майже те саме при великих N
print(wald(0, 100))          # (0.0, 0.0)          — абсурд
print(wilson(0, 100))        # (0.0, 0.03699)      — розумно

Звіт A/B-тесту "конверсія 28.8%" без інтервалу нічого не вартий: продакт не відрізнить реальне покращення від шуму, тому GrowthBook, Statsig та інші показують оцінку разом з інтервалом. Так само p̂ = 0.288 ± 0.009 (95%). 08 Скільки shots треба для похибки ±1%

Ключова навичка туторіалу: перетворити вимогу до точності на кількість shots і назад.

Хочемо, щоб |p̂ − p| ≤ ε (ε — «епсилон») з довірою 1 − δ (δ — «дельта»). З нормального наближення: z·√(p(1−p)/N) ≤ ε, звідки

N ≥ z² · p(1 − p) / ε²

p заздалегідь невідоме, тож беремо гірший випадок p(1−p) ≤ 1/4:

N ≥ (z / 2ε)² → ε = 0.01, z = 1.96: N ≥ (1.96 / 0.02)² = 98² = 9604

Варіанти, які варто тримати в голові:

  • ±1% як 1σ (68% впевненості): N = 0.25/0.01² = 2500.
  • ±1% з 95%: 9604 — найчастіша відповідь на співбесіді.
  • ±1% з 99%: (2.576/0.02)² ≈ 16 590 (≈ — «приблизно дорівнює»).
  • Якщо відомо, що p ≈ 0.1, то N = 1.96²·0.09/0.0001 ≈ 3458 — майже втричі менше за гірший випадок.

Гарантія без наближень: нерівність Хеффдінга

Нормальне наближення — саме наближення. Якщо потрібна гарантія для будь-якого p і будь-якого N (наприклад, у формальному звіті чи в теоремі про алгоритм), використовують нерівність Хеффдінга для обмежених величин у [0, 1]:

P(|p̂ − p| ≥ ε) ≤ 2·exp(−2Nε²) → N ≥ ln(2/δ) / (2ε²)

Для ε = 0.01, δ = 0.05: N ≥ ln(40)/0.0002 ≈ 18 445. Удвічі більше, ніж 9604: ціна за гарантію без припущень. На практиці беруть нормальне наближення, у статтях з теоретичними оцінками складності — Хеффдінга або Чернова.

check_9604.py
import numpy as np
from qiskit import QuantumCircuit
from qiskit_aer import AerSimulator

qc = QuantumCircuit(1)
qc.h(0)
qc.measure_all()
sim = AerSimulator()

def experiment(shots, runs=400, seed0=1000):
    est = []
    for s in range(runs):
        counts = sim.run(qc, shots=shots, seed_simulator=seed0 + s).result().get_counts()
        est.append(counts.get("0", 0) / shots)
    return np.array(est)

e = experiment(9604)
print(np.mean(np.abs(e - 0.5) <= 0.01))  # 0.9525  ← теорія: 0.95
print(e.std())                          # 0.00510 ← теорія: 0.5/√9604 = 0.00510

e = experiment(2500, seed0=5000)
print(np.mean(np.abs(e - 0.5) <= 0.01))  # 0.6625  ← теорія: ~0.68 (це ±1σ)

Збіг з теорією в межах статистики самого експерименту (400 повторів дають власну похибку ~1%). Тобто формула N = (z/2ε)² — не абстракція, а робочий інструмент планування бюджету QPU.

⚠️
Ця формула про статистичну похибку, а не про правильність відповіді. На реальному QPU 9604 shots дадуть оцінку ±1% навколо зашумленого значення. Якщо апаратний шум зсунув p з 0.5 до 0.515, ви дуже точно виміряєте 0.515. Більше shots не лікують систематичну похибку — дивіться розділ 10.

09 Precision в EstimatorV2 ↔ shots

Як Qiskit Runtime дозволяє задавати точність замість shots.

У SamplerV2 ви задаєте shots напряму. В EstimatorV2 замість цього задають precision — цільову стандартну похибку оцінки очікуваного значення. Для одного оператора Паулі (власні значення ±1, дисперсія ≤ 1) з розділу 5 маємо SE ≤ 1/√N, тому

shots ≈ 1 / precision²

За документацією IBM Runtime, precision за замовчуванням дорівнює 0.015625 = 1/64, тобто 1/√4096 — приблизно 4096 shots на схему (перевірте актуальне значення в документації вашої версії qiskit-ibm-runtime: дефолти змінювались).

estimator_precision.py
import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import SparsePauliOp
from qiskit_aer.primitives import EstimatorV2

qc = QuantumCircuit(1)
qc.ry(1.2, 0)                         # ⟨Z⟩ = cos(1.2) = 0.36236
obs = SparsePauliOp("Z")

for prec in (0.05, 0.01):
    vals = []
    for s in range(200):
        est = EstimatorV2(options={"run_options": {"seed": s}})
        res = est.run([(qc, obs)], precision=prec).result()[0]
        vals.append(float(res.data.evs))
    print(prec, np.mean(vals), np.std(vals), float(res.data.stds))

# 0.05  ~0.364  ~0.05   0.05   ← розкид ≈ заявленій precision
# 0.01  ~0.362  ~0.010  0.01   (точні цифри трохи різняться між запусками)

Нюанс Aer проти справжнього QPU. Aer-івський EstimatorV2 обчислює точне значення і додає гаусів шум з σ = precision — це модель статистики shots, а не реальний семплінг. 11 Шум зчитування, умовні ймовірності і Байєс

Детектор кубіта іноді помиляється. Модель цього — матриця 2×2 умовних ймовірностей.

Нехай істинний стан після схеми — біт t ∈ {0, 1}, а прочитаний — r. Зчитування описують умовні ймовірності P(r | t): "яка ймовірність прочитати r, якщо насправді t". Їх збирають у матрицю плутанини (confusion / assignment matrix), стовпці якої відповідають істинному стану:

M = [ P(r=0|t=0) P(r=0|t=1) ; P(r=1|t=0) P(r=1|t=1) ] = [ 0.98 0.05 ; 0.02 0.95 ]

Кожен стовпець у сумі дає 1 (з істинного стану ми щось точно прочитаємо). Зверніть увагу на асиметрію: |1⟩ помиляється частіше (5%), бо надпровідний кубіт може релаксувати в |0⟩ просто під час довгого зчитування (процес T1). Це типова картина для реального заліза. За формулою повної ймовірності виміряний розподіл — це добуток матриці на істинний:

p_виміряне = M · p_істинне

Формула Байєса: "що насправді було, якщо я прочитав 1?"

Матриця M відповідає на питання "що я прочитаю за відомого стану". Часто потрібне обернене: прочитали 1 — наскільки ймовірно, що стан справді |1⟩? Це апостеріорна ймовірність:

P(t=1 | r=1) = P(r=1|t=1)·P(t=1) / [ P(r=1|t=1)·P(t=1) + P(r=1|t=0)·P(t=0) ]

При рівних апріорних 0.5: 0.95·0.5 / (0.95·0.5 + 0.02·0.5) = 0.95/0.97 ≈ 0.979. А якщо стан |1⟩ сам по собі рідкісний (апріорна 0.1), то 0.095 / (0.095 + 0.018) ≈ 0.841: кожне шосте "1" — хибне! Це той самий ефект, що й у медичних тестах на рідкісні хвороби, і він важливий для квантових алгоритмів, де правильна відповідь — рідкісний бітрядок.

12 Корекція зчитування: інверсія матриці плутанини

Найпростіша форма error mitigation — це розв'язати систему лінійних рівнянь 2×2.

Якщо p_вим = M·p_іст, то p_іст = M⁻¹·p_вим. M вимірюють калібруванням: готують |0⟩, міряють багато разів (отримують перший стовпець), потім |1⟩ (другий стовпець). Для 2×2:

M = [a b; c d], M⁻¹ = 1/(ad − bc) · [d −b; −c a]

Для нашої M: det = 0.98·0.95 − 0.05·0.02 = 0.930, M⁻¹ ≈ [1.0215 −0.0538; −0.0215 1.0538].

Перевірка на Aer: з моделлю шуму M та 100 000 shots стан |+⟩ дав виміряні (0.5174, 0.4826); після np.linalg.solve(M, p) — (0.4994, 0.5006). Систематичний зсув прибрано, залишилась лише статистика.

⚠️
Масштабування. Для n кубітів повна матриця має розмір 2ⁿ × 2ⁿ: при n = 20 це вже ~10¹² елементів. На практиці припускають незалежність помилок кубітів (тензорний добуток 2×2 матриць, див. туторіал 7) або використовують готові методи: M3 (matrix-free measurement mitigation) і TREX (twirled readout error extinction), який вмикається в EstimatorV2 опціями resilience (див. туторіал 3). Інверсія 2×2 — це фундамент, на якому вони стоять.

13 Порівняння розподілів: TVD, Hellinger, χ²

"Наскільки отримане схоже на очікуване?" — числом, а не на око.

Total variation distance (TVD)

TVD(P, Q) = ½ · Σₓ |P(x) − Q(x)| ∈ [0, 1]

Тлумачення: максимальна різниця ймовірностей будь-якої події під P і під Q. TVD = 0.05 означає, що жоден "класифікатор" не відрізнить ці розподіли з перевагою більше 5% за один shot.

Hellinger fidelity

BC = Σₓ √(P(x)·Q(x)), F_H = BC² ∈ [0, 1]

Коефіцієнт Бхаттачар'ї BC — "скалярний добуток" коренів розподілів (аналог перекриття станів). У Qiskit є готова функція qiskit.quantum_info.hellinger_fidelity(counts1, counts2), яка приймає counts напряму. Ми перевірили: для прикладу нижче вона повертає 0.94997, що збігається з BC² вручну.

Чи це взагалі той розподіл? Тест χ²

Щоб відрізнити "шум shots" від "схема робить не те", порівнюють спостережувані кількості Oₓ з очікуваними Eₓ = N·pₓ:

χ² = Σₓ (Oₓ − Eₓ)² / Eₓ, ступенів свободи = (кількість результатів) − 1

Якщо χ² (χ — «хі») більше за критичне значення (для 3 ступенів свободи і рівня 5% це 7.81), розбіжність не пояснюється статистикою shots. Умова застосовності: усі Eₓ ≥ 5. Для одного біта це еквівалентно z-тесту: z = (p̂ − p₀)/√(p₀(1−p₀)/N), і |z| > 1.96 — сигнал, що щось не так.

💡
Нюанс для QPU: з великим N будь-який тест "виявить" розбіжність, бо реальне залізо завжди трохи шумить. На мільйоні shots χ² скаже "не той розподіл" навіть для чудового QPU. Тому в практиці квантових тестів дивляться на TVD або fidelity з порогом ("TVD < 0.05 — ок"), а χ² використовують для симуляторів і юніт-тестів, де шуму бути не повинно.

14 Кореляції в стані Белла: що статистика каже про заплутаність

Чому counts лише в одному базисі не доводять, що стан заплутаний.

Стан Белла |Φ⁺⟩ = (|00⟩ + |11⟩)/√2 (Φ — «фі велика») у Z-базисі дає "00" і "11" по 50%. Маргінальні розподіли кожного кубіта — чиста монетка (⟨Z₀⟩ = ⟨Z₁⟩ = 0), але біти ідеально корельовані: ⟨Z₀Z₁⟩ = 1. Коваріація Cov(Z₀, Z₁) = ⟨Z₀Z₁⟩ − ⟨Z₀⟩⟨Z₁⟩ = 1, коефіцієнт кореляції теж 1.

Але точно таку ж статистику в Z-базисі дає класична суміш: "з імовірністю ½ готуємо |00⟩, інакше |11⟩". Різниця проявляється в іншому базисі. Додамо H на обидва кубіти перед вимірюванням (вимірюємо X⊗X (⊗ — «тензорно»: тензорний (кронекерів) добуток)):

Строге формулювання цієї ідеї — нерівність CHSH (Белла): комбінація чотирьох кореляцій у різних базисах для будь-якої класичної моделі не перевищує 2, а квантова механіка дозволяє до 2√2 ≈ 2.83. Її теж оцінюють з counts, і похибку рахують тими самими формулами SE (детальніше — у Nielsen & Chuang, §2.6).

15 Утиліти на Python: усе з туторіалу в одному модулі

Невеликий модуль постобробки, який варто мати в кожному квантовому проєкті (і з яким зручно перевіряти задачі).

qstats.py
"""Статистика для counts з квантового комп'ютера. Ключі — бітрядки Qiskit (правий біт = кубіт 0)."""
import math
import numpy as np
from scipy.stats import norm

def probs(counts: dict[str, int]) -> dict[str, float]:
    n = sum(counts.values())
    return {k: v / n for k, v in counts.items()}

def z_expectation(counts: dict[str, int], qubits: list[int]) -> tuple[float, float]:
    """⟨∏ Z_i⟩ для кубітів qubits і його стандартна похибка."""
    n = sum(counts.values())
    total = 0
    for bits, c in counts.items():
        parity = sum(int(bits[-1 - q]) for q in qubits) % 2   # bits[-1] — кубіт 0
        total += c * (1 - 2 * parity)
    ev = total / n
    se = math.sqrt(max(0.0, 1 - ev**2) / n)                   # Var одного shot = 1 − ⟨Z⟩²
    return ev, se

def shots_needed(eps: float, conf: float = 0.95, p: float = 0.5) -> int:
    """Скільки shots, щоб |p̂ − p| ≤ eps з довірою conf (нормальне наближення)."""
    z = norm.ppf(0.5 + conf / 2)
    return math.ceil(z**2 * p * (1 - p) / eps**2)

def shots_hoeffding(eps: float, delta: float = 0.05) -> int:
    return math.ceil(math.log(2 / delta) / (2 * eps**2))

def correct_readout_1q(p_meas, m) -> np.ndarray:
    """p_true = M⁻¹ · p_meas, з обрізанням до валідного розподілу."""
    p = np.linalg.solve(np.asarray(m, float), np.asarray(p_meas, float))
    p = np.clip(p, 0, None)
    return p / p.sum()

def tvd(p: dict[str, float], q: dict[str, float]) -> float:

Графічне пояснення — у розділі 13. TVD 0.05 і fidelity 0.95 — хороший результат для 2-кубітної схеми на реальному QPU.

Задача 21СередньоShots для гамільтоніана

H = 0.5·Z₀ + 0.3·Z₀Z₁ + 0.2·Z₁, усі доданки вимірюються в Z-базисі однією схемою. Скільки shots гарантує SE(⟨H⟩) ≤ 0.01?

Для кожного shot значення h = 0.5·z₀ + 0.3·z₀z₁ + 0.2·z₁, де zᵢ = ±1. Отже |h| ≤ 0.5 + 0.3 + 0.2 = 1, і дисперсія одного shot не перевищує (Σ|cᵢ|)² = 1.

SE ≤ 1/√N ≤ 0.01 → N ≥ 10 000. Це оцінка з запасом: фактична дисперсія залежить від стану і зазвичай менша. Загальне правило: N ≥ (Σ|cᵢ| / precision)². Для гамільтоніанів з великими коефіцієнтами (хімія, QUBO зі штрафами з туторіалу 4) це число швидко росте — ще одна причина нормувати коефіцієнти.

Задача 22СкладноЦе шум shots чи баг у схемі?

(а) Очікуєте 50/50, отримали 5300 / 4700 з 10 000. (б) Отримали 520 / 480 з 1000. (в) Схема H⊗H має давати рівномірний розподіл на 4 результати; з 1000 shots отримали {260, 240, 255, 245}. (г) А якщо {290, 220, 260, 230}?

(а) SE = √(0.25/10000) = 0.005, z = (0.53 − 0.5)/0.005 = 6.0. Ймовірність такого відхилення випадково ~2·10⁻⁹. Не статистика: систематичний зсув (шум зчитування, неточний кут повороту).

(б) SE = √(0.25/1000) ≈ 0.0158, z = 0.02/0.0158 ≈ 1.26, p-value ≈ 0.21. Цілком узгоджується з 50/50. Та сама різниця 2% — але при меншому N вона в межах шуму. Відповідь залежить від N!

(в) Очікувано по 250. χ² = (10² + 10² + 5² + 5²)/250 = 250/250 = 1.0, 3 ступені свободи, p-value ≈ 0.80. Критичне значення 7.81 далеко — розподіл узгоджується з рівномірним.

(г) χ² = (40² + 30² + 10² + 20²)/250 = 3000/250 = 12.0 > 7.81, p-value ≈ 0.007. На симуляторі без шуму це майже напевно баг; на реальному QPU — шум, який варто з'ясувати (порівняйте з калібруванням зчитування).

Задача 23СкладноЗаплутаний стан чи класична суміш?

Хтось стверджує, що приготував стан Белла. У Z-базисі отримано лише "00" і "11" приблизно порівну. Потім додали H на обидва кубіти і отримали {"00": 252, "01": 248, "10": 255, "11": 245}. Обчисліть ⟨X₀X₁⟩ і зробіть висновок.

Після H на обидва кубіти Z-вимірювання дорівнює X-вимірюванню вихідного стану, тож ⟨X₀X₁⟩ = парність нових counts: (252 + 245 − 248 − 255)/1000 = −0.006, SE ≈ 0.032. Статистично це нуль.

Для |Φ⁺⟩ має бути ⟨XX⟩ = +1 (на Aer: {"00": 509, "11": 491}). Нуль у X-базисі при ідеальній кореляції в Z-базисі — підпис класичної суміші {|00⟩, |11⟩}: фаза між компонентами втрачена (декогеренція або CNOT подали на некогерентний стан). Порівняння гістограм — у розділі 14.

Висновок: щоб стверджувати заплутаність, потрібні кореляції щонайменше у двох несумісних базисах. Сама по собі гістограма в Z-базисі нічого не доводить.
