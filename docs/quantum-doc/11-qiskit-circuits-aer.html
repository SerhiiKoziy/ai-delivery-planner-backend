02 Анатомія схеми

Регістри, гейти, бар'єр, вимірювання і метрики, які ви будете дивитись постійно.

Квантова схема — це послідовність інструкцій над кубітами і класичними бітами. Математично кожен гейт — унітарна матриця (туторіали 6 і 7), а схема — їхній добуток. Для фронтендера схема дуже схожа на waterfall у вкладці Performance/Network DevTools: горизонтальні доріжки — кубіти (як треки main thread, worker, network), час іде зліва направо, а вертикальні з'єднання — двокубітні взаємодії, де дві доріжки мусять "синхронізуватись", як await на результат іншого потоку.

from qiskit import QuantumCircuit, QuantumRegister, ClassicalRegister

qr = QuantumRegister(2, "q")

qc = QuantumCircuit(qr, cr, name="bell")

for inst in qc.data[:2]:

03 Порядок бітів: little-endian

Пастка номер один у Qiskit. Пройдіть її свідомо один раз — і не попадайтесь потім у проді.

У Qiskit кубіт 0 — наймолодший біт. У рядку результату '001' він стоїть праворуч, як у звичайному двійковому числі: |q₂ q₁ q₀⟩. Підручники (Nielsen & Chuang) часто пишуть навпаки — |q₀ q₁ q₂⟩. Тому формули з книжки й вивід Qiskit можуть "не збігатися", хоча обидва правильні.

s3_bit_order.py
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector
from qiskit.primitives import StatevectorSampler

qc = QuantumCircuit(3)
qc.x(0)                                   # перевертаємо ЛИШЕ кубіт 0
sv = Statevector(qc)
print({str(k): float(v) for k, v in sv.probabilities_dict().items()})

qc.measure_all()
counts = StatevectorSampler(seed=7).run([qc], shots=100).result()[0].data.meas.get_counts()
print(counts)
print("індекс базисного стану:", int("001", 2))   # = 1 → x0·2⁰

04 Композиція блоків

Схеми як функції: склеювати, вкладати, обертати, підносити до степеня, робити керованими.

s4_compose.py
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator

# Блок, який будемо перевикористовувати
prep = QuantumCircuit(2, name="prep")
prep.h(0)
prep.cx(0, 1)

main = QuantumCircuit(3)
main.compose(prep, qubits=[1, 2], inplace=True)   # вклеїти гейти "як є"
main.append(prep.to_gate(), [0, 1])               # вставити як один блок-гейт
print(main.draw("text"))

undo = prep.inverse()                              # U† : гейти у зворотному порядку
print(undo.draw("text"))
print("prep·undo == I ?", Operator(prep.compose(undo)).equiv(Operator(QuantumCircuit(2))))

t = QuantumCircuit(1, name="T")
t.t(0)
s_from_t = t.power(2)                              # T² = S
s_ref = QuantumCircuit(1); s_ref.s(0)
print("T^2 == S ?", Operator(s_from_t).equiv(Operator(s_ref)))

ch = QuantumCircuit(1, name="H"); ch.h(0)
cH = ch.to_gate().control(1)                       # керований H
c = QuantumCircuit(2); c.append(cH, [0, 1])
print(c.draw("text"))
print(Operator(c).data.round(3))

05 Параметризовані схеми

Шаблон схеми з "дірками" під числа — основа всіх варіаційних алгоритмів (VQE, QAOA).

У варіаційних алгоритмах класичний оптимізатор сотні разів міняє кути і просить QPU перерахувати енергію. Будувати схему з нуля щоразу дорого; правильно — один раз зібрати шаблон з Parameter, один раз транспілювати, а потім лише підставляти значення. Для бекендера — це prepared statement: план запиту будується раз, параметри біндяться при кожному виклику.

s5_params.py
import numpy as np
from qiskit import QuantumCircuit
from qiskit.circuit import Parameter, ParameterVector

theta = Parameter("θ")
phis = ParameterVector("φ", 2)

ansatz = QuantumCircuit(2)
ansatz.ry(theta, 0)
ansatz.ry(phis[0], 1)
ansatz.cx(0, 1)
ansatz.rz(phis[1] + 2 * theta, 1)   # параметричні вирази теж можна
print(ansatz.draw("text"))
print("parameters:", ansatz.parameters)   # відсортовані за іменем
print("num_parameters:", ansatz.num_parameters)

bound = ansatz.assign_parameters({theta: np.pi / 2, phis: [0.1, 0.2]})
print(bound.draw("text"))

# позиційно — у порядку ansatz.parameters
bound2 = ansatz.assign_parameters([0.1, 0.2, np.pi / 2])
print(bound2 == bound)

from qiskit import QuantumCircuit

theta = Parameter("θ"); phis = ParameterVector("φ", 2)
ansatz = QuantumCircuit(2)

print([p.name for p in ansatz.parameters])
wrong = ansatz.assign_parameters([0.1, 0.2, np.pi / 2])   # "як я написав у коді"
right = ansatz.assign_parameters([np.pi / 2, 0.1, 0.2])   # як у ansatz.parameters
print("wrong == bound:", wrong == bound)
print("right == bound:", right == bound)

06 Statevector і SparsePauliOp

Точна математика без шуму і без shots — ваш "unit-тест" для малих схем.

qiskit.quantum_info рахує все точно, як NumPy (і, власне, через NumPy): вектор стану з 2ⁿ комплексних амплітуд, оператори як матриці 2ⁿ×2ⁿ. Тому він ідеальний для перевірки логіки на 2–20 кубітах і безнадійний для 50+. Ви вже написали подібне вручну в туторіалі 10 — тут те саме, але готове.

s6_quantum_info.py
import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector, SparsePauliOp, Operator

bell = QuantumCircuit(2)
bell.h(0)
bell.cx(0, 1)

sv = Statevector.from_instruction(bell)      # або Statevector(bell)
print(np.round(sv.data, 3))
print({str(k): round(float(v), 3) for k, v in sv.probabilities_dict().items()})
print({str(k): complex(np.round(v, 3)) for k, v in sv.to_dict().items()})

zz = SparsePauliOp("ZZ")
zi = SparsePauliOp("ZI")                      # Z на кубіті 1 (лівий символ = старший кубіт)
xx = SparsePauliOp("XX")
for name, op in [("ZZ", zz), ("ZI", zi), ("XX", xx)]:
    print(name, round(float(sv.expectation_value(op).real), 3))

h = SparsePauliOp.from_list([("ZZ", 1.0), ("XI", -0.5), ("IX", -0.5)])
print(h)
print("⟨H⟩ =", round(float(sv.expectation_value(h).real), 3))
print(np.round(h.to_matrix().real, 2))
print(SparsePauliOp.from_sparse_list([("Z", [2], 1.0)], num_qubits=3))

Що тут відбулось:

  • Амплітуди [0.707, 0, 0, 0.707] — стан Белла (|00⟩ + |11⟩)/√2 (|00⟩ — «кет нуль-нуль»: вектор-стовпчик стану; √ — «корінь з»).

  • SparsePauliOp — гамільтоніан як сума Pauli-рядків з коефіцієнтами. Саме в такому вигляді задачі оптимізації (QUBO → Ising, туторіал 4) і хімії подаються в Estimator. to_matrix() — для перевірки руками на малих розмірах.
  • from_sparse_list — зручно для великих систем: "Z на кубіті 2 з 3" без ручного вписування I.

Математика: ⟨ψ|H|ψ⟩ = Σᵢ cᵢ ⟨ψ|Pᵢ|ψ⟩ (⟨ψ|H|ψ⟩ — «бра псі, H, кет псі»: середнє (очікуване) значення H у стані ψ; ⟨ψ| — «бра псі»: рядок, спряжено-транспонований кет; Σ — «сума», велика сигма) — очікування лінійне, тому Estimator міряє кожен Pauli-рядок окремо і складає з вагами. Деталі — в туторіалі 9 (дисперсія і shots).

07 Operator: рівність схем і глобальна фаза

Як довести, що дві схеми роблять одне й те саме, — і чому == іноді бреше.

s7_equivalence.py
import numpy as np
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator

# 1) CNOT = (I⊗H)·CZ·(I⊗H)
a = QuantumCircuit(2); a.cx(0, 1)
b = QuantumCircuit(2); b.h(1); b.cz(0, 1); b.h(1)
print("CX ≡ H·CZ·H :", Operator(a).equiv(Operator(b)))

# 2) SWAP = три CNOT
s = QuantumCircuit(2); s.swap(0, 1)
c3 = QuantumCircuit(2); c3.cx(0, 1); c3.cx(1, 0); c3.cx(0, 1)
print("SWAP ≡ 3·CX :", Operator(s).equiv(Operator(c3)))

# 3) Глобальна фаза: RZ(π) = -i·Z
rz = QuantumCircuit(1); rz.rz(np.pi, 0)
z = QuantumCircuit(1); z.z(0)
print("RZ(π) == Z   :", Operator(rz) == Operator(z))       # точна рівність матриць
print("RZ(π) ≡ Z    :", Operator(rz).equiv(Operator(z)))   # з точністю до глобальної фази
print(np.round(Operator(rz).data, 3))

RZ(π) = diag(−i, i) = −i·Z (π — «пі»). Матриці різні (== → False), але відрізняються лише глобальною фазою −i, яку не можна виміряти жодним експериментом (туторіал 8). equiv() порівнює саме з точністю до глобальної фази — у тестах майже завжди потрібен він. Те саме видно у виводі транспілятора: global phase: 3π/4 — транспілятор її відстежує, але на залізі вона нічого не змінює.

Аналогія для фронтендера
Глобальна фаза — як transform: rotate(30deg) на корені всієї сцени, коли користувач бачить лише взаємне розташування елементів: повернули все разом — для "виміру" нічого не змінилось. Відносна фаза — як rotate() лише на одному дочірньому елементі: тепер змінилось, як елементи накладаються один на одного, і це видно (у квантовому випадку — через інтерференцію). Тому Operator.equiv порівнює "з точністю до повороту всієї сцени", а == — побітово, як snapshot-тест, що падає навіть на нерелевантній різниці.
Де аналогія ламається: у CSS поворот усієї сцени все ж видно відносно вікна браузера; у квантовому стані "вікна" немає — глобальна фаза не спостережувана в принципі.

08 Навіщо транспіляція: ISA

Ваша схема написана "мовою високого рівня". Чип розуміє 5 гейтів і має обмежені з'єднання.

Реальний процесор IBM Heron (FakeFez — його знімок калібрувань) вміє лише rz, sx, x, id і двокубітний cz, і лише між фізично сусідніми кубітами. Аналогія для бекендера
Транспіляція — це query planner + компілятор під конкретний CPU. Одна і та сама SQL-квері має різні плани для різних індексів; одна і та сама схема має різні ISA-схеми для різних чипів і навіть для того самого чипа в різні дні (калібрування змінюються).
Аналогія для фронтендера
Транспіляція — це Babel/SWC + бандлер із browserslist. Basis gates — синтаксис, який підтримує цільовий браузер: усе, чого немає (H, CX), переписується в те, що є (RZ, SX, CZ), як optional chaining у старий ES5. Coupling map — які API реально доступні на таргеті; коли двокубітний гейт просять між несусідніми кубітами, транспілятор вставляє SWAP-и — як поліфіли, що збільшують бандл (тут — глибину й помилку). optimization_level 0–3 — рівні terser/мініфікатора: довше збирається, менший результат. ISA-схема — уже скомпільований під конкретний таргет бандл: запускати на іншому чипі його не можна.
Де аналогія ламається: "таргет" тут не лише тип чипа, а й його сьогоднішні калібрування — той самий бандл завтра може бути не оптимальним.

from qiskit.primitives import StatevectorSampler

def oracle(kind):
    o = QuantumCircuit(N + 1, name=f"U_f[{kind}]")
    if kind == "const0":

        o.x(N)                            # f(x) = 1

Задача 22СкладноGrover на 3 кубітах: скільки ітерацій

Реалізуйте загальний Гровер (оракул і дифузор через mcx) для цілі '101' серед N = 8 станів. Порахуйте P(101) для 0–4 ітерацій і порівняйте з формулою P_k = sin²((2k+1)·θ), де sin θ = 1/√N. Чому "більше ітерацій" — гірше?

task22.py
import numpy as np
from qiskit import QuantumCircuit
from qiskit.primitives import StatevectorSampler

def phase_flip(target: str) -> QuantumCircuit:
    n = len(target)
    o = QuantumCircuit(n, name="oracle")
    zeros = [i for i, b in enumerate(reversed(target)) if b == "0"]
    if zeros: o.x(zeros)
    o.h(n - 1); o.mcx(list(range(n - 1)), n - 1); o.h(n - 1)   # multi-controlled Z
    if zeros: o.x(zeros)
    return o

def diffuser(n: int) -> QuantumCircuit:
    d = QuantumCircuit(n, name="diffuser")
    d.h(range(n)); d.compose(phase_flip("0" * n), inplace=True); d.h(range(n))
    return d

def grover(target: str, iterations: int) -> QuantumCircuit:
    n = len(target)
    qc = QuantumCircuit(n); qc.h(range(n))
    for _ in range(iterations):
        qc.compose(phase_flip(target), inplace=True)
        qc.compose(diffuser(n), inplace=True)
    qc.measure_all()
    return qc

n, N = 3, 8
k_opt = int(np.floor(np.pi / 4 * np.sqrt(N)))
print("оптимум ітерацій:", k_opt)
for k in range(0, 5):
    c = StatevectorSampler(seed=3).run([grover("101", k)], shots=4000).result()[0].data.meas.get_counts()
    theo = np.sin((2 * k + 1) * np.arcsin(1 / np.sqrt(N))) ** 2
    print(f"k={k}: P('101') = {c.get('101', 0)/4000:.3f}  теорія {theo:.3f}")

Для бекенду це означає: кількість ітерацій — параметр, який треба рахувати, а не "чим більше, тим краще". Якщо кількість розв'язків невідома — використовують варіації з випадковою кількістю ітерацій або quantum counting.
