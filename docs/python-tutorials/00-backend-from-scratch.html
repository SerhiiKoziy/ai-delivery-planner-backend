Чому ми: ядро продукту — оптимізація маршрутів (OR-Tools) і AI (OpenAI, парсинг Excel). Усі три найкраще підтримуються саме в Python. CPU-слабкість не критична: важку частину рахує C++ всередині OR-Tools, а не Python.

Чому 3.12: швидший інтерпретатор (3.11+ дав ~25% приросту), сучасний синтаксис типів (list[str], X | None), datetime.UTC; усі наші залежності його підтримують.

Мінус, який варто визнати вголос: якщо CRUD-навантаження виросте до десятків тисяч RPS, Python потребуватиме більше інстансів, ніж Go. Але це проблема масштабу, якої ще немає — і вона розв'язується горизонтально.

🧠 Запам'ятай: Python обраний не "бо простий", а бо OR-Tools + OpenAI + pandas — це серце продукту, а важкі обчислення все одно йдуть у C++.

04 Архітектура: шари і правило залежностей

Вирішуємо структуру до того, як з'явиться перший бізнес-код, — потім переробляти дорого.

api/ — HTTP
→
services/ — логіка
→
repositories/ — SQL
→
db/models/ — таблиці

Правило залежностей: кожен шар імпортує тільки шари нижче. Роутер не пише SQL, репозиторій не знає про HTTP-коди, сервіс не знає про Request. Поперек усіх шарів ідуть schemas/ (контракти даних) і core/ (конфіг, безпека, DI).

services/Бізнес-правила, оркестрація кількох репозиторіїв і клієнтівHTTP, Request, статус-коди

Чому ми: для одного сервісу з однією БД і маленькою командою шари дають достатньо структури без церемоній Clean Architecture. Всередині services/route_optimizer/ ми вже групуємо за фічею (builder, solver, mapper) — підходи комбінуються.

Коли б змінив: якщо команда виросте до кількох груп, що працюють над різними доменами, — перейшов би до vertical slices / модульного моноліту, а не одразу до мікросервісів.

🧠 Запам'ятай: api → services → repositories → models, залежності лише вниз; це "модульний моноліт-лайт": достатньо структури, без оверхеду Clean Architecture і мікросервісів.

05 Конфігурація: pydantic-settings і .env

Секрети й налаштування — лише зі змінних оточення, ніколи в коді (12-factor app).

app/core/config.py
from functools import lru_cache

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    """Типізований конфіг: значення беруться з env / .env і валідуються."""

    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    APP_NAME: str = "Delivery Backend"
    ENVIRONMENT: str = "local"
    DEBUG: bool = True                      # "false" з env → False (Pydantic сам приведе)

    DATABASE_URL: str = "postgresql+asyncpg://postgres:postgres@localhost:5432/delivery"
    REDIS_URL: str = "redis://localhost:6379/0"

    JWT_SECRET: str = "change-me"
    JWT_ALGORITHM: str = "HS256"
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 30
    REFRESH_TOKEN_EXPIRE_MINUTES: int = 60 * 24 * 7

    OPENAI_API_KEY: str = ""
    GOOGLE_MAPS_API_KEY: str = ""

    CORS_ORIGINS: list[str] = ["http://localhost:3000"]   # з env — JSON-рядок


@lru_cache
def get_settings() -> Settings:
    """Один екземпляр на процес; у тестах можна перевизначити."""
    return Settings()

10 Репозиторії: доступ до БД + ізоляція орендарів

app/repositories/base.py
from typing import Generic, TypeVar

from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

ModelType = TypeVar("ModelType")


class BaseRepository(Generic[ModelType]):
    def __init__(self, session: AsyncSession, model: type[ModelType]) -> None:
        self.session = session
        self.model = model

    async def get(self, id) -> ModelType | None:
        return await self.session.get(self.model, id)

    async def list(self) -> list[ModelType]:
        stmt = select(self.model).order_by(self.model.created_at.desc())
        return list((await self.session.execute(stmt)).scalars().all())

    async def create(self, **kwargs) -> ModelType:
        instance = self.model(**kwargs)
        self.session.add(instance)
        await self.session.commit()
        await self.session.refresh(instance)
        return instance

    async def update(self, id, **kwargs) -> ModelType | None:
        instance = await self.get(id)          # для tenant-версії — вже scoped get
        if instance is None:
            return None
        for key, value in kwargs.items():
            setattr(instance, key, value)
        await self.session.commit()
        await self.session.refresh(instance)
        return instance

    async def delete(self, id) -> bool:
        instance = await self.get(id)
        if instance is None:
            return False
        await self.session.delete(instance)
        await self.session.commit()
        return True


class TenantScopedRepository(BaseRepository[ModelType]):
    """organization_id задається ОДИН раз у конструкторі (з токена через DI) —
    немає жодного методу, де можна забути відфільтрувати за організацією."""

    def __init__(self, session: AsyncSession, model: type[ModelType], organization_id) -> None:
        super().__init__(session, model)
        self.organization_id = organization_id

    async def get(self, id) -> ModelType | None:
        stmt = select(self.model).where(
            self.model.id == id, self.model.organization_id == self.organization_id
        )
        return (await self.session.execute(stmt)).scalar_one_or_none()

    async def list(self) -> list[ModelType]:
        stmt = (
            select(self.model)
            .where(self.model.organization_id == self.organization_id)
            .order_by(self.model.created_at.desc())
        )
        return list((await self.session.execute(stmt)).scalars().all())

    async def create(self, **kwargs) -> ModelType:
        kwargs.pop("organization_id", None)    # клієнт не може "підсунути" чужу організацію
        return await super().create(organization_id=self.organization_id, **kwargs)

    async def update(self, id, **kwargs) -> ModelType | None:
        kwargs.pop("organization_id", None)    # і не може перенести рядок в іншу
        return await super().update(id, **kwargs)


class DeliveryRepository(TenantScopedRepository[Delivery]):
    def __init__(self, session: AsyncSession, organization_id) -> None:

from datetime import UTC, datetime, timedelta

from jose import JWTError, jwt
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
settings = get_settings()


class InvalidTokenError(Exception):
    """Наш власний тип — решта коду не залежить від бібліотеки JWT."""


def hash_password(plain: str) -> str:
    return pwd_context.hash(plain)                 # bcrypt: повільний навмисно + сіль


def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)


def _create_token(subject: str, token_type: str, expires: timedelta) -> str:
    now = datetime.now(UTC)
    claims = {"sub": subject, "type": token_type, "iat": now, "exp": now + expires}
    return jwt.encode(claims, settings.JWT_SECRET, algorithm=settings.JWT_ALGORITHM)


def create_access_token(user_id: str) -> str:
    return _create_token(user_id, "access", timedelta(minutes=settings.ACCESS_TOKEN_EXPIRE_MINUTES))


def create_refresh_token(user_id: str) -> str:
    return _create_token(user_id, "refresh", timedelta(minutes=settings.REFRESH_TOKEN_EXPIRE_MINUTES))


def decode_token(token: str) -> dict:
    try:
        return jwt.decode(token, settings.JWT_SECRET, algorithms=[settings.JWT_ALGORITHM])
    except JWTError as exc:                        # підпис, формат, прострочення
        raise InvalidTokenError(str(exc)) from exc

    user_repo: UserRepository = Depends(get_user_repository),

    except InvalidTokenError as exc:

    user = await user_repo.get(uuid.UUID(claims["sub"]))
    if user is None:                         # користувача видалили після видачі токена
        raise credentials_error
    return user

app/core/rate_limiting.py — fixed window по IP
import time
from collections import defaultdict, deque
from threading import Lock

_WINDOWS: dict[str, deque] = defaultdict(deque)
_LOCK = Lock()


def rate_limit_by_ip(scope: str, max_requests: int, window_seconds: float):
    """Фабрика FastAPI-залежності: не більше max_requests за window_seconds з однієї IP."""

    def _dependency(request: Request) -> None:
        key = f"{scope}:{request.client.host if request.client else 'unknown'}"
        now = time.monotonic()
        with _LOCK:
            window = _WINDOWS[key]
            while window and now - window[0] > window_seconds:
                window.popleft()                       # викидаємо застарілі
            if len(window) >= max_requests:
                raise HTTPException(status_code=429, detail="Too many requests.")
            window.append(now)

    return _dependency


register_rate_limiter = rate_limit_by_ip("register", max_requests=5, window_seconds=3600)
login_rate_limiter = rate_limit_by_ip("login", max_requests=20, window_seconds=60)

async def try_consume_quota(self, organization_id, *, counter_column: str, limit: int | None) -> bool:
    """ОДИН запит UPDATE ... WHERE лічильник + 1 <= ліміт.
    Не "прочитати → перевірити → записати": два паралельні запити
    не зможуть обидва пройти останню одиницю квоти."""
    column = getattr(Organization, counter_column)
    stmt = update(Organization).where(Organization.id == organization_id)
    if limit is not None:
        stmt = stmt.where(column + 1 <= limit)
    stmt = stmt.values(**{counter_column: column + 1})
    result = await self.session.execute(stmt)
    await self.session.commit()
    return result.rowcount > 0          # 0 рядків оновлено → квота вичерпана

Питання, якими "атакують" — і відповіді

Чому не Django — там же все є?
Нам не потрібні адмінка й шаблони: це чистий JSON API для SPA з великою кількістю I/O. FastAPI дає async, валідацію й OpenAPI з type hints. Ціна — збираємо ORM/міграції/auth самі, але це 3 свідомі рішення, а не тисяча неявних. Якби потрібна була внутрішня адмінка для операторів — Django був би сильним кандидатом.
Навіщо репозиторії, якщо SQLAlchemy — і так абстракція?
SQLAlchemy абстрагує SQL-діалект, а репозиторій — правила доступу. Головне: TenantScopedRepository вшиває фільтр організації, тож у сервісі неможливо забути WHERE organization_id. Плюс одне місце для запитів і легкі підміни в тестах.
Що буде, якщо два запити одночасно витратять останню одиницю квоти?
Пройде лише один. Перевірка і інкремент — один UPDATE ... SET x = x + 1 WHERE x + 1 <= limit; Postgres блокує рядок на час оновлення, другий запит побачить уже нове значення й оновить 0 рядків. Read-modify-write у Python тут дав би гонку.
Чому in-memory rate limiter? Це ж не масштабується.
Так, і це задокументовано: Fly.io налаштований на одну машину й один процес. Для поточного навантаження це нуль інфраструктури. Квоти на платні API — в БД, вони масштабуються. Коли знадобиться друга машина — лічильники переїжджають у Redis (той, що вже є для Celery), інтерфейс залежності не змінюється.
Чому тести на SQLite, а продакшн — Postgres?
Швидкість і нуль інфраструктури: весь набір проходить за секунди, CI без сервісів. Ризик — різниця діалектів (enum, блокування, конкурентність). Тому конкурентну логіку квот треба додатково тестувати на справжньому Postgres — це перше покращення CI.
Як ви не блокуєте event loop солвером, який рахує секунди?
asyncio.to_thread: солвер виконується в пулі потоків, а event loop обслуговує інші запити. OR-Tools — C++, він відпускає GIL під час пошуку, тому потоки тут ефективні. Для довших задач — Celery-воркер і відповідь 202 + опитування статусу.
JWT вкрали — що робити?
Access живе 30 хвилин — шкода обмежена в часі. Поле type не дає використати refresh як access. Для миттєвого відкликання — ротація refresh-токенів і список відкликаних у Redis, або зміна JWT_SECRET як аварійний "вийти всім".
Як масштабувати, якщо навантаження зросте в 10 разів?
По порядку, від дешевого: (1) rate limiter → Redis, щоб дозволити кілька машин; (2) fly scale count N — застосунок stateless; (3) пул з'єднань і PgBouncer перед Postgres; (4) солвер → Celery-воркери, що масштабуються окремо; (5) індекси за повільними запитами, read-репліки для дашбордів; (6) кеш у Redis для геокодування однакових адрес. Мікросервіси — лише якщо різні частини справді потребують різного масштабу.
Чому commit усередині репозиторію — це ж погано для транзакцій?
Чесно — це компроміс на користь простоти. Для однокрокових операцій проблем немає. Для багатокрокових (маршрут + зупинки + лічильник) правильніше Unit of Work: сесія комітиться один раз наприкінці операції, а при помилці — rollback усього. Це наступний рефакторинг.
Чому 404, а не 403, для чужих даних?
403 підтверджує, що ресурс існує, — це витік інформації (можна перебирати id). Для клієнта "чуже" і "не існує" мають бути невідрізненні.

27 Самоперевірка

Відповідайте вголос, потім відкривайте. Повторіть завтра і через тиждень.

1. Назвіть 4 шари і що кожен НЕ має знати.
api (не знає SQL), services (не знає HTTP), repositories (не знає бізнес-правил і HTTP), db/models (нічого вище).
2. Звідки береться organization_id у запиті до БД?
Тільки з автентифікованого користувача (JWT → get_current_user → user.organization_id → конструктор репозиторію). Від клієнта — ніколи, і репозиторій викидає його з kwargs.
3. Чим access-токен відрізняється від refresh і як сервер їх розрізняє?
Час життя (30 хв vs 7 днів) і призначення; поле type у claims, яке перевіряє get_current_user та /refresh.
4. Навіщо expire_on_commit=False?
Щоб після commit атрибути об'єкта лишались доступними без нового запиту — в async SQLAlchemy неявний lazy-запит при доступі до атрибута впав би.
5. Що autogenerate в Alembic може зробити небезпечно?
Перейменування колонки згенерує drop + add (втрата даних); не бачить зміни значень enum і backfill даних. Тому міграції читаємо очима.
6. Чому квота перевіряється ДО виклику Google/OpenAI і як — атомарно?
Щоб відхилений запит не коштував грошей; одним UPDATE ... WHERE лічильник + 1 <= ліміт, rowcount показує, чи пройшло.
7. Що станеться, якщо викликати requests.get в async-ендпоінті?
Заблокується event loop — увесь процес не обслуговує інші запити до кінця виклику. Потрібен httpx.AsyncClient або to_thread.
8. Як тести обходяться без Postgres, JWT і OpenAI?
app.dependency_overrides: get_db → SQLite in-memory сесія, get_current_user → тестовий юзер, get_openai_client → фейковий клієнт; геокодер — monkeypatch AsyncMock.
9. Чому в Dockerfile спершу копіюється pyproject.toml, а потім код?
Кеш шарів: встановлення залежностей перезбирається лише при зміні pyproject, а не при кожній зміні коду.
10. Що робить release_command і чому міграції саме там?
Запускає alembic upgrade head в окремій машині до перемикання трафіку; якщо міграція впаде — нова версія не стартує, стара продовжує працювати.
11. Чому застосунок обмежений однією машиною і що змінити, щоб зняти обмеження?
Rate limiter зберігає стан у пам'яті процесу; перенести лічильники в Redis.
